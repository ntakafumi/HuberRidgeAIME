# HuberRidgeAIME

[![DOI](https://zenodo.org/badge/1257880530.svg)](https://doi.org/10.5281/zenodo.20520654)

This repository contains the reproducibility materials for:

**HuberRidgeAIME: Robust Model-Agnostic Explanations under Outliers and Multicollinearity**

## Current corrected notebooks

Only the following three notebooks are current for the revised manuscript:

```text
notebooks/HuberRidgeAIME_Main_Reproducibility_CORRECTED.ipynb
notebooks/HuberRidgeAIME_Supplementary_Classwise_and_Synthetic_Visuals_CORRECTED.ipynb
notebooks/HuberRidgeAIME_Additional_Robustness_Faithfulness_Experiments.ipynb
```

All AIME-family estimators in these notebooks use the inverse-map formulation in the manuscript:

\[
X \approx Y A^\top,
\]

where `Y` is the black-box output matrix and `X` is the input-feature matrix.
Huber residuals are row-wise RMS residuals in input space.
Coefficient norm is reported only as a regularization diagnostic, not as an explanation-quality metric.

The default full runs use `seed = 42`, `lambda = 0.01`, and `delta = 1.0`.
The JSON run-configuration file generated by each notebook is the authoritative record of the complete experimental settings.

## Division of responsibility

### Main reproducibility notebook

`HuberRidgeAIME_Main_Reproducibility_CORRECTED.ipynb` is the source for the current manuscript's main experiments and core tabular results.
It produces:

- the three-dataset audit;
- the corrected clean benchmark;
- the controlled-stress comparison of AIME, HuberAIME, RidgeAIME, and HuberRidgeAIME;
- paired condition-cluster bootstrap confidence intervals;
- the Australian Credit imputation versus complete-case comparison;
- runtime scaling;
- CSV data, LaTeX tables, PNG figures, provenance metadata, an environment manifest, a validation report, and a SHA-256 artifact manifest.

Its default output directory is:

```text
./output/main_repro_corrected/
```

The full-run validation gates require 108 clean-benchmark rows, 972 controlled-stress rows, 72 missing-data rows, and 144 runtime rows.
They also require passing inverse-map unit tests, no experiment errors, `X ~= Y A^T` in every applicable row, all four AIME-family methods in the stress experiment, finite key metrics, and a nonempty condition-cluster confidence-interval table.

The corrected manuscript figures are written with the filenames already used by the current LaTeX source:

```text
fig_revision_log_condition_number_boxplot.png
fig_revision_log_coef_norm_boxplot.png
fig_revision_metric_discrimination_decoy.png
fig_revision_runtime_scaling.png
```

### Established Supplementary visuals notebook

`HuberRidgeAIME_Supplementary_Classwise_and_Synthetic_Visuals_CORRECTED.ipynb` regenerates the established Supplementary Figures S1--S10 rather than replacing their roles with unrelated figures. It produces:

- nine class-wise signed global-feature-importance panels for three datasets by three learners;
- six separate explainer panels within each figure: AIME, HuberAIME, RidgeAIME, HuberRidgeAIME, LIME, and SHAP;
- the controlled synthetic heatmap for AIME-family stability, noise robustness, and decoy resistance;
- raw CSV data, dataset/model audit data, figure provenance, run configuration, an environment manifest, strict validation results, SHA-256 hashes, and a ZIP package.

Its default output directory is:

```text
./output/supplementary_legacy_corrected/
```

The nine panel filenames and `synthetic_heatmaps.png` are unchanged from the current Supplementary LaTeX source. The synthetic parameter $\rho$ now controls correlation in the output design `Y`, because the corrected inverse-map normal system is based on `Y.T @ Y`; outliers are injected into rows of `X`. The full synthetic run contains 1,600 method-level rows (4 correlation levels by 4 outlier levels by 25 matched repeats by 4 AIME-family methods). Validation also requires all 54 dataset/learner/explainer cells and all ten figure files.

### Additional validation notebook

`HuberRidgeAIME_Additional_Robustness_Faithfulness_Experiments.ipynb` is the source for additional robustness, faithfulness, sensitivity, and baseline validation experiments.
It produces:

- fixed-black-box contamination and end-to-end HRA-versus-RidgeAIME comparisons;
- known-ground-truth faithfulness experiments;
- the zero-operator control;
- `lambda` and `delta` sensitivity analyses;
- separate measurements for correlated clones and true irrelevant permutation decoys;
- standard LIME and native LightGBM TreeSHAP stress comparisons;
- spectral diagnostics for `Y` and `sqrt(W)Y`;
- manuscript-ready Supplementary Figures S11--S16, leaving the established S1--S10 figure roles intact;
- CSV data, LaTeX tables, PNG figures, provenance metadata, an environment manifest, a validation report, and a SHA-256 artifact manifest.

Its configured full-run output directory is:

```text
./output/additional_validation_manuscript_figures/
```

The full-run validation gates require 540 fixed-protocol rows, 324 end-to-end rows, 900 synthetic rows, 864 sensitivity rows, and 72 baseline rows.
They also require the correct inverse-map orientation, no experiment errors, finite condition-cluster confidence intervals, genuine LightGBM, standard LIME, and finite spectral diagnostics for the relevant design matrices.

The three notebooks contain related experiments but do not use identical protocols for every end-to-end result.
Use the main notebook for the manuscript's main real-data tables and figures.
Use the established-visuals notebook for Supplementary Figures S1--S10.
Use the additional validation notebook for the focused experiments and Supplementary Figures S11--S16 listed above.
Do not mix similarly named end-to-end results across the protocols.

## Installation

The release files pin one common Python environment for all three notebooks. The `shap` package is required by the established class-wise panels; the additional validation notebook continues to use LightGBM's native contribution implementation for its TreeSHAP stress comparison.

Using Conda:

```bash
conda env create -f environment.yml
conda activate hra-corrected-2026
```

Using `pip` in a Python 3.13.2 environment:

```bash
python -m pip install -r requirements.txt
```

## Full execution

All output paths are relative to the process working directory.
Run the following commands from the repository root to generate the result directories:

```bash
jupyter nbconvert --execute --to notebook --inplace \
  notebooks/HuberRidgeAIME_Main_Reproducibility_CORRECTED.ipynb
jupyter nbconvert --execute --to notebook --inplace \
  notebooks/HuberRidgeAIME_Supplementary_Classwise_and_Synthetic_Visuals_CORRECTED.ipynb
jupyter nbconvert --execute --to notebook --inplace \
  notebooks/HuberRidgeAIME_Additional_Robustness_Faithfulness_Experiments.ipynb
```

This produces:

```text
output/main_repro_corrected/
output/supplementary_legacy_corrected/
output/additional_validation/
```

These generated result directories are intentionally excluded from the GitHub repository and Zenodo software archive.
They can be regenerated from the three notebooks and are ignored by `.gitignore`.

A fresh full run requires network access to download the Australian Credit and HAR data.
The notebooks are configured with full-run defaults and forced recomputation.

3. Create a GitHub Release from that tag. A tag alone is not the GitHub Release archived by the Zenodo integration.
4. Confirm in Zenodo's GitHub settings that `ntakafumi/HuberRidgeAIME` is enabled before publishing the GitHub Release.
5. Open the newly archived Zenodo version and verify its files, title, authors, ORCID identifiers, license, description, keywords, and version.
6. Use the new version-specific DOI in the revised manuscript because it identifies the exact archived package used for the submission.
7. Use the concept DOI when referring to the evolving software project across versions.
8. After Zenodo displays the new record, verify whether the README badge links to the concept DOI or an older version-specific DOI. Keep the concept DOI for an all-versions badge; if the link is version-specific, update `main` to the concept DOI without creating another release solely for the badge change.
